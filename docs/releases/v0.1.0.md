# v0.1.0 release candidate

Status: candidate. Public release and installation checks remain pending.

## Product promise

writing-doc turns AI output into clear, useful documentation your audience can understand and act on.
It puts the answer first and preserves facts, commands, links, warnings, and necessary conditions.
It keeps the user's language.

## Clients and installation

The package supplies one shared skill for Codex, Claude Code, and clients that support Agent Skills.
Client manifests point to that skill. They do not prove client installation or runtime behavior.

The [English README](../../README.md) and [Chinese README](../../README.zh-CN.md) describe each route:

- `skills` CLI: select a client and installation scope.
- Codex Skill Installer: install the shared skill from the tagged skill path.
- Claude Code: register the repository marketplace, then install its local plugin.
- Manual copy: copy the entire `skills/writing-doc` directory into the client's skill directory.

All remote routes remain `Planned for v0.1.0 verification`.
The public release identity is `joevilcai666/writing-doc-skill`, branch `main`, and annotated tag `v0.1.0`.
These names describe the intended release. They do not establish public availability.

## Scope and contents

The skill covers README files, procedures, tutorials, API documentation, and technical design documents.
For review-only requests, it reports problems and specific corrections without file edits.
Its scope excludes marketing copy, literary text, and file conversion without a documentation task.

The package includes:

- One authoritative skill and portable, Codex, and Claude package manifests.
- English and Chinese documentation under the MIT license.
- Four approved 1200 × 1200 PNG images and one 1280 × 640 social preview.
- One synthetic before-and-after guide, a deterministic rubric, and local checks.
- The deterministic archive builder, tests, and release evidence template.

The release assets are `writing-doc-skill-v0.1.0.zip` and `writing-doc-skill-v0.1.0.zip.sha256`.
The ZIP uses one `writing-doc-skill/` directory, fixed timestamps, fixed permissions, and sorted file paths.
The builder uses tracked current files. It excludes design plans, local validator state, local SDD state, and `dist/`.
The archive contains no Git history.

## Known limits

The synthetic guide illustrates a target result. It is not a measured agent output or evidence of reader comprehension.
Public clone, download, installation, runtime, directory discovery, and user acceptance remain pending.
See the [verification template](../verification/v0.1.0.md) and [distribution status](../distribution.md).

The private development history contains five earlier PNG blobs with private metadata.
The current PNGs pass the metadata check, but publication requires a clean reviewed public history.
The installed Codex CLI has no plugin validator. This missing required validator blocks the release gate.
The archive builder does not remove or weaken either publication requirement.

The file privacy gate accepts strict UTF-8 and UTF-16 or UTF-32 with a BOM, plus valid PNG files.
It rejects unknown encodings, invalid bytes, and forbidden control characters before archive output.
This gate applies to current files, index blobs, and reachable history, including deleted files.
Invalid-content findings contain fixed redacted details without the original filename or decoder error.

The package adds no analytics, telemetry, remote service, or background process.
Agents, model providers, tools, and installers apply their own data policies.
The skill does not supply missing facts or guarantee correct output.
The local privacy scanner detects fixed patterns. It cannot prove that all private information is absent.
